Help / Guide

Start a workspace, then build a repeatable literature-review routine.

This is a local, single-user application. The browser handles projects, searches, schedules, history, and paper inspection. Use the desktop client for settings, review changes, tags, exports, and recovery. Both clients share the application services and can use the same local data directory; there is no automatic cross-device sync.

First-Time Setup — install, connect, and run your first search

1. Install and launch

Open a terminal in the repository folder. Skip virtual-environment creation if .venv already exists. Choose your operating system's commands:

Linux / macOS (Bash)

python3 -m venv .venv
.venv/bin/python -m pip install -e '.[web]'
.venv/bin/python -m research_engine.web.main --monitor

Windows (PowerShell)

py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[web]"
.\.venv\Scripts\python.exe -m research_engine.web.main --monitor

Open http://127.0.0.1:8000. Keep the terminal running; use Ctrl+C to stop and allow active work to shut down. Do not use Windows executable paths in a Linux terminal.

Startup creates the database and applies migrations. The default workspace is .research-scrapper-engine in your home directory. Append --data-dir ./web-pilot for a separate trial, or --port 8001 for a different port. An existing DATABASE_URL overrides the database location even with --data-dir. Keep the default localhost binding: this release has no public-hosting login system.

If reusing data collected with version 0.1.0, rebuild or audit it before relying on it. Upgrading does not repair historical PubMed identity errors; follow docs/DATA_INTEGRITY_REMEDIATION.md.

2. Choose sources and connection settings

Start with PubMed and Europe PMC. OpenAlex and Crossref are also supported. The browser's source checkboxes select sources for a query; a source must also be allowed by saved discovery settings.

For settings, stop this server and open the desktop client on the same data directory. Install the desktop extra and launch:

Linux / macOS

.venv/bin/python -m pip install -e '.[desktop]'
.venv/bin/research-engine-desktop

Windows PowerShell

.\.venv\Scripts\python.exe -m pip install -e ".[desktop]"
.\.venv\Scripts\research-engine-desktop.exe
  • Settings → Sources: choose defaults for new queries and sources allowed during monitoring. Edit existing queries separately to change their saved sources.
  • API access: configure contact email and optional keys. Set NCBI_API_KEY or OPENALEX_API_KEY in the environment before starting the web process when needed. Desktop session keys are neither saved to disk nor shared with a separate web process.
  • Network: enable a reachable HTTP/SOCKS5/SOCKS5H proxy explicitly, or leave it disabled for direct requests. Proxy URLs with embedded credentials are not supported. A 403 error does not automatically enable a proxy.
  • Workflow: choose default result/page budgets, monitoring interval, and whether exports include excluded papers.

Restart the browser server after settings changes. If the browser used --data-dir ./web-pilot, set RESEARCH_ENGINE_DATA_DIR to that same directory before starting desktop: export RESEARCH_ENGINE_DATA_DIR="$PWD/web-pilot" in Bash, or $env:RESEARCH_ENGINE_DATA_DIR = "$PWD/web-pilot" in PowerShell. Check DATABASE_URL as well if set. Do not run desktop and web schedulers simultaneously against the same workspace.

3. Create a research project

In Project workspace, create and select a project such as “Breast cancer immunotherapy.” It groups your saved queries and collected papers. Separate projects can represent separate research questions.

4. Build and save a query

("breast cancer" OR "triple negative breast cancer") AND immunotherapy NOT mice

Enter the expression, select sources, and wait for a valid Expression preview. Read each source's translation and notices, then save. Save as new query creates a separate query; Edit query → Save changes updates the selected one and retains its history.

The editor is a draft until saved. Runs and schedules use the selected saved query, not unsaved text. Set advanced date/language/publication filters in the desktop query editor; browser edits retain existing filters.

5. Run and inspect

Select the saved query and choose Run search. Start with a small Pages per source budget. Check Recent activity and Query history & monitoring, then open a paper title to inspect metadata and provenance. Open publication page opens an external page; access depends on that site. No PDFs are downloaded.

Check partial/failed source outcomes before interpreting the result count. A bounded search is not an exhaustive literature review.

6. Enable monitoring

Select the saved query, enable its schedule, set the interval in minutes, and choose Save schedule. New schedules default to 60 minutes (1 hour) between source API searches. Existing schedules retain their saved interval; change it to 60 and save for hourly searches. Automatic polling requires the server's --monitor option and allowed monitoring sources. The next run becomes due after the interval.

Run due executes due queries across projects, not every query immediately. Use Run search for immediate execution. Closing the browser tab does not stop the server; stopping the server stops monitoring.

Ongoing Workflow — monitor, track duplicates, review, and export

1. Refine Boolean expressions

  • cancer AND immunotherapy: require both terms.
  • Alzheimer OR dementia: accept alternatives.
  • cancer NOT mice: exclude a term.
  • (Alzheimer OR dementia) AND "artificial intelligence": group alternatives and require a phrase.

Operators are case-insensitive outside quotes. Precedence is NOT, then AND, then OR. Adjacent words imply AND: use "breast cancer" for a phrase. NOT alpha beta means (NOT alpha) AND beta; use NOT "alpha beta" or NOT (alpha OR beta) for different exclusions.

Incomplete quotes, parentheses, or operators prevent saving. Provider-specific field tags, wildcards, and proximity syntax are not portable query syntax. Always inspect the preview after editing.

PubMed, Europe PMC, and OpenAlex receive source-specific Boolean translations. Crossref retrieves candidates and filters their available title/abstract/subject metadata. Missing metadata, source indexing, and bounded page budgets affect recall; NOT means absent from available metadata, not proof of clinical irrelevance. Equivalent queries can return different papers across sources. Prefer a positive topic clause to a negative-only query.

2. Understand the records and duplicate tracking

A project contains saved queries and links to shared canonical papers. Query revisions, attempts, and provider runs preserve search history. Paper observations link to source identifiers and immutable raw responses. Review state and tags belong to the project-paper link, not the shared paper.

DOI, PMID, PMCID, and provider identifiers identify known records. The same paper found through multiple queries or sources normally appears once in a project's library, with each source observation retained. Similar titles or conflicting identifiers are flagged rather than silently merged. Use desktop Identity review… for available decisions.

  • Newly discovered: first encountered by this installation—even if published years ago.
  • Newly published: within the publication-recency window; it may already be known.
  • Updated metadata: a known paper changed, not a new paper.
  • Seen again: more search/source evidence for an existing record.

Run “New” counts concern newly discovered canonical records, not necessarily every paper newly visible in this project. Citation counts are source-specific, not summed. Zero new papers can still mean known papers were found or updated.

3. Check monitoring and history

Activity, papers, and history refresh automatically once per minute; use Refresh now for an immediate check, including after a running search finishes. Recent activity scrolls within one viewport's maximum height. Browser refresh reads local results, not literature APIs. The server checks due schedules every minute by default; source APIs are searched for due enabled queries (hourly by default for new schedules) or manual searches. Inspect provider runs, execution attempts, scheduled executions, and coverage checkpoints, not only the latest activity message.

  • Completed: finished within the recorded execution's scope.
  • Partial: work/coverage remains, such as a page-budget limit or a failed source alongside successful sources.
  • Failed: inspect the issue; it is not evidence that no papers match.
  • Running / skipped: wait for active work or inspect why an attempt was not executed.

Monitoring combines recent-publication checks with continuing full-query coverage. Saved cursors continue bounded campaigns on later scheduled runs; overlapping recent windows help revisit late-indexed or changed records. Your date filters still apply. Source limits and changing indexes prevent an exhaustive-coverage guarantee.

Keep only one scheduler process for a workspace. After a crash, stop remaining workers before using desktop Recovery…. Recovery is explicit; do not assume every interrupted attempt resumed. Recent activity jobs are temporary, but stored run history survives restarts. There are no email/push alerts yet.

4. Review papers and organize tags

Use the desktop client to change these values; the browser currently displays them only.

  • Mark read: marks read and clears an important/excluded decision.
  • Mark important: marks important without automatically marking read; an existing read timestamp remains.
  • Exclude: retains the paper and evidence, flags it excluded in this project, and preserves an existing read timestamp.
  • Reset to unread: clears the read timestamp and the important/excluded decision.

The displayed status prioritizes important/excluded; a paper can be important and already read. Use review/read filters and Show excluded. Select a paper and use project tag controls to add or remove tags. Other projects' reviews/tags are unaffected.

5. Export and back up

Select the project in the desktop client and choose Export CSV or Export RIS. CSV suits spreadsheets; RIS suits reference managers. Exports include canonical metadata and project review/tag context where supported. Some reference managers ignore RIS notes. Excluded papers are included by default; change this in Settings if needed.

Exports are not backups: queries, full history, and raw snapshots are not preserved. For local SQLite, stop all clients/workers and copy the complete data directory, including the database, snapshots, and settings. Restore into a clean directory, launch using that directory, and verify projects, papers, queries, and history. Environment API keys are not in backups. Custom database locations and PostgreSQL need the separate installation/backup instructions.

6. Resolve common issues

Optionally use the browser's Google Sheets sync card to connect a Sheet to this project. Set the service-account JSON file path on the server, share the Sheet with that account as Editor, and choose Sync now for the first upload. Enabled links sync after scheduled searches. The separate app-managed tab displays Last successful update (UTC), and local status shows the last success or a safe error code. Manual searches need a manual sync. This is a one-way projection, not a backup or import; see docs/GOOGLE_SHEETS.md for setup.

  • Browser unavailable: check the server terminal and localhost port.
  • Cannot save: select a project and allowed sources, then fix preview errors.
  • Source disabled: check desktop discovery settings and saved query sources.
  • No scheduled updates: check --monitor, schedule enabled state, due time, and monitoring allow-list. Run due does not force a future-due query.
  • 403/authentication/quota error: inspect run details, credentials, service limits, and explicitly configured reachable proxy if appropriate.
  • Empty results: check filters, expression, provider outcomes, and page budget before concluding no papers match.
  • Empty workspace after restart: check the data directory and DATABASE_URL.
